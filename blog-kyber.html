KYBER — The Lattice Lock

2026-08-15 · ~12 MIN READ · CLEARANCE: PUBLIC
Kyber LWE Post-Quantum ML-KEM QuMail

RSA has been the backbone of internet encryption since 1977. In a post-quantum world, it is dead. This transmission documents CRYSTALS-Kyber (now standardized as ML-KEM by NIST) — the lattice-based Key Encapsulation Mechanism that replaces everything you thought was secure. This is the same scheme running inside QuMail.

00 // WHY RSA DIES

RSA's security rests on one assumption: factoring large integers is hard. For classical computers, it is. But Shor's algorithm, running on a sufficiently powerful quantum computer, factors \(N = pq\) in polynomial time — specifically \(O((\log N)^2 (\log \log N)(\log \log \log N))\) using quantum modular exponentiation.

The same applies to Elliptic Curve Cryptography (ECC) — the discrete logarithm problem on elliptic curves falls to Shor's equally. Every TLS handshake, every SSH key, every PGP signature currently deployed is retroactively vulnerable the moment a cryptographically relevant quantum computer (CRQC) exists.

This is not theoretical paranoia. Nation-states are running "harvest now, decrypt later" campaigns — intercepting encrypted traffic today and storing it for quantum decryption later. The ciphertext you send today may be read in 2030.

01 // THE LATTICE FOUNDATION

Kyber is built on lattice cryptography — specifically the Module Learning With Errors (MLWE) problem. Before diving into Kyber, you need to understand what a lattice is and why finding things in one is hard.

A lattice \(\mathcal{L}\) in \(\mathbb{R}^n\) is the set of all integer linear combinations of \(n\) linearly independent basis vectors \(\mathbf{b}_1, \dots, \mathbf{b}_n\):

$$\mathcal{L}(\mathbf{B}) = \left\{ \sum_{i=1}^{n} z_i \mathbf{b}_i \;\middle|\; z_i \in \mathbb{Z} \right\}$$

Think of it as a regular grid in high-dimensional space. The Shortest Vector Problem (SVP) asks: given a basis for \(\mathcal{L}\), find the shortest nonzero vector. In 2D this is trivial — in 500+ dimensions, it is believed to be exponentially hard, even for quantum computers.

The Learning With Errors (LWE) problem, introduced by Oded Regev in 2005, connects lattice hardness to cryptographic schemes. Given a secret vector \(\mathbf{s} \in \mathbb{Z}_q^n\), you are given many noisy linear equations:

$$\mathbf{b} = \mathbf{A}\mathbf{s} + \mathbf{e} \pmod{q}$$

where \(\mathbf{A} \in \mathbb{Z}_q^{m \times n}\) is a random matrix and \(\mathbf{e}\) is a small error vector sampled from a discrete Gaussian or centered binomial distribution. The challenge: recover \(\mathbf{s}\) given \((\mathbf{A}, \mathbf{b})\). Without the error, this is trivial linear algebra (Gaussian elimination). With error, it becomes as hard as worst-case lattice problems.

02 // KYBER'S MODULE-LWE VARIANT

Kyber doesn't use plain LWE — it uses Module-LWE, which works over the polynomial ring \(R_q = \mathbb{Z}_q[X]/(X^{256}+1)\). Each "entry" in the matrix is a polynomial of degree 255, not just an integer. This gives you:

  • Smaller keys — a \(k \times k\) matrix of polynomials replaces a massive \(n \times n\) integer matrix
  • Faster operations — polynomial multiplication via Number Theoretic Transform (NTT), analogous to FFT over finite fields
  • Tunable security — adjust \(k\) for different security levels (Kyber-512, 768, 1024)

03 // KEY GENERATION

Alice generates her keypair:

  1. Sample a random matrix \(\mathbf{A} \in R_q^{k \times k}\) from a seed (public, deterministic via SHAKE-128)
  2. Sample secret vector \(\mathbf{s} \in R_q^k\) with small coefficients from \(\text{CBD}_\eta\) (centered binomial distribution)
  3. Sample error vector \(\mathbf{e} \in R_q^k\) from \(\text{CBD}_\eta\)
  4. Compute public key: \(\mathbf{t} = \mathbf{A}\mathbf{s} + \mathbf{e}\)
$$\text{pk} = (\mathbf{t}, \rho) \qquad \text{sk} = \mathbf{s}$$

where \(\rho\) is the seed for regenerating \(\mathbf{A}\). The public key is \(\mathbf{t}\) — the noisy product — plus the seed. The secret key is \(\mathbf{s}\).

04 // ENCAPSULATION

Bob wants to establish a shared secret with Alice. He:

  1. Generates a random 256-bit message \(m\)
  2. Derives randomness: \((\bar{K}, r) = G(m \| H(\text{pk}))\) via SHA3-512
  3. Samples his own secret/error vectors \(\mathbf{r}, \mathbf{e}_1, e_2\) using \(r\) as seed
  4. Computes the ciphertext components: $$\mathbf{u} = \mathbf{A}^T \mathbf{r} + \mathbf{e}_1$$ $$v = \mathbf{t}^T \mathbf{r} + e_2 + \lceil q/2 \rfloor \cdot m$$
  5. Compresses and sends ciphertext \(c = (\text{Compress}(\mathbf{u}), \text{Compress}(v))\)
  6. Derives shared secret: \(K = \text{KDF}(\bar{K} \| H(c))\)

The genius: the message \(m\) is encoded by adding \(\lceil q/2 \rfloor \cdot m\) to the noisy inner product. This pushes the encoded bit to either ~0 or ~q/2 — far enough apart that the noise doesn't cross the decision boundary.

05 // DECAPSULATION

Alice receives the ciphertext and recovers the shared secret:

  1. Decompress \(\mathbf{u}\) and \(v\)
  2. Compute \(m' = \text{Compress}_1(v - \mathbf{s}^T \mathbf{u})\)
  3. Re-encrypt \(m'\) using the public key to get \(c'\)
  4. If \(c' = c\): output \(K = \text{KDF}(\bar{K}' \| H(c))\) — same as Bob's
  5. If \(c' \neq c\): output a random key (implicit rejection — prevents chosen-ciphertext attacks)

Why does the math work? The decryption computes:

$$v - \mathbf{s}^T\mathbf{u} = \mathbf{t}^T\mathbf{r} + e_2 + \lceil q/2 \rfloor m - \mathbf{s}^T(\mathbf{A}^T\mathbf{r} + \mathbf{e}_1)$$ $$= (\mathbf{A}\mathbf{s}+\mathbf{e})^T\mathbf{r} + e_2 + \lceil q/2 \rfloor m - \mathbf{s}^T\mathbf{A}^T\mathbf{r} - \mathbf{s}^T\mathbf{e}_1$$ $$= \mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1 + \lceil q/2 \rfloor m$$

The terms \(\mathbf{e}^T\mathbf{r} + e_2 - \mathbf{s}^T\mathbf{e}_1\) are all products of small vectors — their sum is bounded and small relative to \(q/2\). So rounding recovers \(m\) exactly.

NIST standardized three security levels:

Note the key sizes: ML-KEM-768's public key is 1184 bytes — roughly 15x larger than an ECDH-256 key (32 bytes). This is the price of quantum resistance. In QuMail, we engineered a fragmented signaling protocol to handle these payloads over WebRTC's constrained signaling channels.

07 // THE NTT TRICK

Polynomial multiplication in \(R_q\) naively costs \(O(n^2)\). Kyber uses the Number Theoretic Transform — essentially FFT over \(\mathbb{Z}_q\) — to reduce this to \(O(n \log n)\):

$$\mathbf{a} \cdot \mathbf{b} = \text{NTT}^{-1}(\text{NTT}(\mathbf{a}) \circ \text{NTT}(\mathbf{b}))$$

This works because \(q = 3329\) was chosen specifically so that \(X^{256}+1\) splits into 128 degree-2 factors modulo \(q\) — enabling a 7-layer butterfly NTT. The entire key generation, encapsulation, and decapsulation become dominated by a handful of NTT calls — each taking microseconds on modern hardware.

08 // WHY NIST CHOSE KYBER

NIST's Post-Quantum Cryptography standardization process (2016–2024) evaluated 69 initial submissions across lattice, code, hash, and multivariate categories. Kyber won for KEM because:

  • Proven hardness — Module-LWE has a worst-case to average-case reduction to hard lattice problems
  • Performance — NTT-based operations are fast on constrained hardware (ARM Cortex-M4 benchmarks)
  • Key/ciphertext sizes — smallest among lattice-based finalists
  • Conservative design — IND-CCA2 security via Fujisaki-Okamoto transform
  • Side-channel resistance — constant-time implementations exist, no branching on secret data

09 // CONNECTION TO QUMAIL

QuMail integrates Kyber KEM into real-time WebRTC video calls. The challenge: Kyber's public keys exceed typical WebRTC signaling payload limits. Our solution uses Firebase-based fragmented signaling:

$$N_{\text{frags}} = \left\lceil \frac{K_{\text{size}}}{\text{MTU}_{\text{eff}}} \right\rceil$$

Each fragment is individually authenticated with a SHA-256 chain hash. The receiver reassembles fragments in order, verifies integrity, and proceeds with Kyber decapsulation. The result: quantum-resistant key exchange over standard WebRTC infrastructure, with a 94% reduction in handshake latency on unstable networks compared to naive approaches.
